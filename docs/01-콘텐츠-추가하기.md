# 01 · 콘텐츠 추가하기

콘텐츠는 전부 `content/` 폴더의 **JSON 파일**에 들어 있습니다.
HTML이나 CSS를 몰라도 이 파일들만 고치면 사이트가 바뀝니다.

---

## JSON 파일을 고칠 때 지켜야 할 4가지

JSON은 규칙이 엄격합니다. 아래만 지키면 깨질 일이 없습니다.

1. **문자열은 반드시 큰따옴표** `"이렇게"` — 작은따옴표 `'이렇게'` 는 안 됩니다.
2. **항목 사이엔 쉼표, 마지막 항목 뒤엔 쉼표 없음.**
   ```jsonc
   "a": "값1",
   "b": "값2"      ← 마지막이므로 쉼표 없음
   ```
3. **중괄호 `{}` 와 대괄호 `[]` 의 개수를 맞춥니다.** 기존 항목을 통째로 복사해 붙여넣고 내용만 바꾸는 것이 가장 안전합니다.
4. **문자열 안에서 큰따옴표를 쓰려면** `\"` 로 씁니다. 줄바꿈은 `\n`.

> 💡 저장 전 검사: [jsonlint.com](https://jsonlint.com) 에 붙여넣으면 문법 오류를 알려줍니다.
> VS Code로 편집하면 잘못된 곳에 빨간 밑줄이 바로 표시됩니다.

**`_comment` 로 시작하는 항목은 설명용 메모입니다. 지우지 말고 그대로 두세요.**

---

## 한국어 / 영어 동시 입력

거의 모든 텍스트는 이런 모양입니다.

```json
"title": { "ko": "한국어 제목", "en": "English Title" }
```

- 영어를 아직 준비하지 못했다면 `"en"` 을 `""` 로 비워 두세요. 한국어가 대신 표시됩니다.
- 사이트 오른쪽 위 `KO / EN` 버튼으로 전환됩니다.

## ① 연구원 추가하기 — `content/people.json`

`members` 배열에서 기존 항목 하나를 복사해 맨 뒤에 붙여넣고 내용만 바꿉니다.

```json
{
  "id": "kim-cheolsu",
  "group": "member",
  "name": { "ko": "김철수", "en": "Cheolsu Kim" },
  "role": { "ko": "석사과정", "en": "M.S. Student" },
  "affiliation": { "ko": "한양대학교 실내건축디자인학과", "en": "Dept. of Interior Architecture Design, Hanyang University" },
  "email": "",
  "keywords": ["Generative Design", "HCI"],
  "photo": "assets/img/people/kim-cheolsu.jpg",
  "links": [{ "label": "Web", "url": "https://example.com" }],
  "since": "2026"
}
```

| 항목 | 설명 |
|---|---|
| `id` | 영문 소문자 + 하이픈. **중복되면 안 됩니다.** |
| `group` | `director` / `faculty` / `member` / `advisor` / `alumni` 중 하나 |
| `photo` | 비워 두면 이름 이니셜이 자동으로 그려집니다 |
| `keywords` | 없으면 `[]` |
| `links` | 없으면 `[]` |

### 졸업 처리

`"group": "member"` → `"group": "alumni"` **한 글자만 바꾸면** 자동으로 졸업생 섹션으로 내려갑니다.
과거 기록이 지워지지 않는 것이 이 사이트의 핵심입니다. **사람을 삭제하지 말고 alumni로 옮기세요.**

### 사진 규격

- 위치: `assets/img/people/`
- 정사각형, 800 × 800 px 권장, JPG, 300KB 이하
- 사이트에서는 흑백으로 표시되고 마우스를 올리면 컬러로 바뀝니다 — 배경이 단순한 사진일수록 잘 나옵니다

## ② 연구 프로젝트 추가하기 — `content/projects.json`

`items` 배열에 새 항목을 넣습니다. (화면 정렬은 날짜순으로 자동 처리되므로 위치는 상관없지만,
관리하기 편하도록 맨 위에 넣는 것을 권합니다.)

```json
{
  "id": "2026-spatial-ux-ai",
  "status": "ongoing",
  "kind": { "ko": "산학협력과제", "en": "Industry Collaboration" },
  "title": { "ko": "프로젝트 이름", "en": "Project Title" },
  "funder": { "ko": "지원 기관", "en": "Funding Agency" },
  "start": "2026-03",
  "end": "2027-02",
  "tags": ["UX", "Spatial Design"],
  "cover": "assets/img/projects/2026-spatial-ux-ai/cover.jpg",
  "summary": { "ko": "목록에 보일 두세 줄 요약", "en": "Short summary" },
  "body": {
    "ko": [
      "첫 번째 문단입니다.",
      "## 연구 목표",
      "- 첫 번째 목표",
      "- 두 번째 목표",
      "![연구 개념도](assets/img/projects/2026-spatial-ux-ai/diagram.jpg)"
    ],
    "en": ["First paragraph.", "## Objectives", "- First objective"]
  },
  "roles": [],
  "gallery": [],
  "links": []
}
```

| 항목 | 설명 |
|---|---|
| `id` | 영문 소문자 + 하이픈. 상세 페이지 주소가 됩니다 |
| `status` | `ongoing`(진행중) 또는 `completed`(종료) |
| `start` / `end` | `"2026-03"` 형식. 종료일 미정이면 `""` |
| `cover` | 대표 이미지. 비워도 됩니다 |

### 본문(`body`) 작성법 — "한 줄에 하나씩"

`body` 는 **줄의 목록**입니다. 각 줄 앞에 기호를 붙여 모양을 정합니다.

| 쓰는 법 | 결과 |
|---|---|
| `"그냥 문장입니다."` | 일반 문단 |
| `"## 소제목"` | 소제목 (밑줄 있는 제목) |
| `"- 항목"` | 파란 점이 붙은 목록 |
| `"> 강조할 문장"` | 왼쪽에 파란 선이 붙은 강조 문단 |
| `"![캡션](이미지경로)"` | 사진 + 캡션 |
| `"**굵게**"` | **굵은 글씨** (문장 안에서) |
| `"[링크 이름](https://...)"` | 링크 (문장 안에서) |

### 참여 기관(`roles`) 쓰는 법

```json
"roles": [
  {
    "label": { "ko": "주관연구기관", "en": "Lead Institution" },
    "people": [
      { "name": { "ko": "홍길동 교수", "en": "Prof. Gildong Hong" },
        "org":  { "ko": "한양대학교", "en": "Hanyang University" } }
    ]
  }
]
```

## ③ 활동 · 뉴스 추가하기 — `content/activities.json`

`items` 배열에 넣습니다. 구조는 프로젝트와 거의 같습니다.

```json
{
  "id": "2026-03-15-open-seminar",
  "category": "seminar",
  "date": "2026-03-15",
  "title": { "ko": "제3회 오픈 세미나", "en": "3rd Open Seminar" },
  "place": { "ko": "한양대학교 생활과학관", "en": "Hanyang University" },
  "cover": "",
  "summary": { "ko": "요약", "en": "Summary" },
  "body": { "ko": ["본문 첫 줄"], "en": ["First line"] },
  "gallery": ["assets/img/activities/2026-03-15/1.jpg"],
  "links": []
}
```

- `category` 는 `news` / `seminar` / `workshop` / `talk` / `award` / `outreach` 중 하나
- 새 분류가 필요하면 같은 파일 위쪽 `categories` 배열에 한 줄 추가하면 필터 버튼이 자동 생성됩니다
- `id` 는 `연도-월-일-영문요약` 형태를 권장합니다 (나중에 찾기 쉽습니다)

---

### 포스터 넣기

포스터가 있는 행사는 `poster` 항목에 경로를 적습니다.

```json
"poster": "assets/img/activities/2026-07-08-hcai-seminar/poster.jpg",
```

- 상세 페이지에서 **본문 왼쪽 / 포스터 오른쪽 2단**으로 나란히 놓입니다
- 포스터는 스크롤을 따라와서, 프로그램을 읽는 내내 함께 보입니다
- 클릭하면 원본이 새 탭에서 열립니다
- 좁은 화면에서는 자동으로 본문 위로 올라갑니다
- 세로형(A4 등) 이미지를 권장합니다. 긴 변 1600px, 300KB 이하로 줄여서 올리세요

> `body` 안에 `![캡션](경로)` 로 이미지를 넣을 수도 있습니다.
> 그때는 본문 흐름 중간에 한 단 폭으로 실립니다. 포스터는 `poster` 항목을 쓰세요.

## ④ 연구 성과 — `content/publications.json`

`논문(paper)` 과 `특허(patent)` 두 갈래이고, **디자인권도 특허 안에** 들어갑니다
(`kind` 로 `patent` / `design` 을 구분). 화면은 `publications.html` 의 탭입니다.

**논문**

```json
{
  "id": "2026-aei-design-lora",
  "type": "paper",
  "title": "Design LoRA: Interactive fine-tuning of text-to-image models…",
  "authors": "Seung Won Lee, Yejin Yun, Kyung Hoon Hyun",
  "venue": "Advanced Engineering Informatics, 76(1)",
  "publisher": "Elsevier",
  "index": "SCIE",
  "date": "2026-11-01",
  "doi": "https://doi.org/10.1016/j.aei.2026.105053"
}
```

| 항목 | 설명 |
|---|---|
| `authors` | **영문 표기**. 논문에 실린 순서 그대로, 쉼표로 구분 |
| `index` | `SCIE` / `SCI` / `SCOPUS` 등. 배지로 표시됩니다 |
| `date` | 출판일자. 이 값으로 연도가 묶이고 정렬됩니다 |
| `doi` | 있으면 제목이 링크가 됩니다. **없으면 비워두세요 — 추정해서 넣으면 엉뚱한 논문으로 갑니다** |

**특허 · 디자인권**

```json
{
  "id": "patent-2026-04-21-context-aware-product-image",
  "type": "patent",
  "kind": "patent",
  "title":     { "ko": "사용자 의도 기반 맥락 반영형 제품 이미지 생성 시스템 및 방법", "en": "" },
  "inventors": { "ko": "현경훈, 최지인, 장유경", "en": "Kyung Hoon Hyun, Jiin Choi, Yugyeong Jang" },
  "country": "KR",
  "filed": "2026-02-23",
  "filingNo": "10-2026-0033081",
  "registered": "2026-04-21",
  "registrationNo": "10-2957285",
  "date": "2026-04-21"
}
```

- `kind` 는 `patent`(특허) 또는 `design`(디자인권)
- `date` 는 정렬·연도 묶음용. **등록됐으면 등록일, 아니면 출원일**을 넣습니다
- 등록 전이면 `registered` / `registrationNo` 는 `""` 로 두세요

> ⚠️ **넣지 말아야 할 것**: 기여율, 과제명·과제번호, 사업자등록번호, IRIS 등록 여부.
> 대외 공개용 페이지이므로 내부 관리 항목은 담지 않습니다.

## ⑤ 메인 페이지에 몇 개까지 보이나요

메인 페이지 아카이브는 **최신순으로 24개**까지 먼저 보여 주고, 그보다 오래된 항목은
아래 **「더 보기」** 버튼으로 펼칩니다. 개수는 `content/site.json` 에서 조절합니다.

```json
"home": {
  "archiveLimit": 24,     // 처음 보여 줄 개수
  "loadMoreStep": 24      // '더 보기' 한 번에 추가로 펼칠 개수
}
```

> 오래된 항목이 **삭제되는 것은 아닙니다.** 접혀 있을 뿐이고,
> 「더 보기」·필터·검색으로 언제든 전부 볼 수 있습니다.
> 아카이브에서 기록이 사라지면 아카이브가 아니게 되므로 일부러 이렇게 했습니다.
> 정말로 목록에서 빼고 싶은 항목은 JSON에서 직접 지우세요(깃 기록에는 남습니다).

정렬은 JSON에 적은 순서와 무관하게 **항상 날짜 최신순**입니다.
`projects` 는 `start`, `activities` 는 `date`, `publications` 는 `year` 기준입니다.
그러니 새 항목을 배열 맨 위에 넣든 맨 아래에 넣든 화면은 똑같이 나옵니다.

## ⑥ 이미지 관리 규칙

```
assets/img/
├── people/                    연구원 사진      (800×800, 정사각형)
├── projects/<프로젝트id>/      프로젝트 이미지  (긴 변 1600px 이하)
├── activities/<날짜-id>/       활동 사진·포스터 (긴 변 1600px 이하)
└── favicon.svg

assets/logo/                   로고 (건드릴 일 거의 없음)
tools/logo/                    로고 생성 도구 — 사이트에 로드되지 않습니다
```

**폴더 이름은 해당 항목의 `id` 와 똑같이** 지으세요. 나중에 어떤 이미지가 어디 것인지 바로 알 수 있습니다.
예: `2026-07-08-hcai-seminar` 활동의 포스터 → `assets/img/activities/2026-07-08-hcai-seminar/poster.jpg`

- **파일명은 영문 소문자 + 숫자 + 하이픈만** 사용하세요. 한글·공백·괄호가 들어가면 주소가 깨질 수 있습니다.
  `연구소 사진(1).jpg` ❌ → `seminar-01.jpg` ✅
- 웹용으로 **긴 변 1600px 이하, 500KB 이하**로 줄여서 올리세요. 원본 그대로 올리면 사이트가 느려집니다.
  (무료 도구: [squoosh.app](https://squoosh.app))
- 이 저장소는 이미지를 그대로 담습니다. 전체 용량이 **1GB를 넘지 않도록** 관리하세요.
  발표 슬라이드 원본, 영상 원본 등 큰 파일은 구글 드라이브에 두고 `links` 로 연결하는 편이 낫습니다.

## ⑦ 저장 후 확인 → 반영

1. `preview.bat` 더블클릭 → 브라우저에서 확인
2. 화면이 비어 있다면 → 브라우저에서 `F12` → Console 탭에 뜬 빨간 오류가 원인입니다. 대부분 JSON 쉼표/따옴표 실수입니다.
3. 확인이 끝나면 [docs/02-깃과-배포.md](02-깃과-배포.md) 의 절차대로 push → 1~2분 뒤 실제 사이트 반영
